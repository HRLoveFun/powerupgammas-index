# PowerUpGammas 视频索引

一个单文件的视频索引页：按时间浏览全部公开视频、按标签筛选、查看视频之间的引用关系并连线。

交付物是**两个自包含页面**（双击即可打开，无需服务器）：

| 文件 | 面向 | 内容 |
|---|---|---|
| `index.html` | 访客 | 只读：浏览、筛选、看引用与笔记。没有任何编辑入口 |
| `dev.html` | 维护者 | 在上面基础上多了笔记编辑、标签/引用维护、待确认队列、导出修订 |

两个页面由同一套源码（`web/`）一次构建产出，共用数据，只是编译时写入的 `__MODE__` 不同。

## 一、数据源核实结论

在动手前对频道做了实测（2026-11），结果决定了后面的方案：

| 数据源 | 可达性 | 实测结论 |
|---|---|---|
| `/videos` 标签页 | ✅ 可用 | `yt-dlp --flat-playlist` 拿到全部 **380** 个视频的 ID 与标题；但**不含发布日期** |
| `/playlists` 标签页 | ✅ 可用 | **15 个播放列表**，覆盖 291 个视频（76%），是唯一可靠的现成分类体系 |
| 单个视频页（默认 UA） | ❌ 被拦 | 返回 `Sign in to confirm you're not a bot`，所有 player client（tv / mweb / ios / android_vr…）均被拦 |
| 单个视频页（爬虫 UA） | ✅ 可用 | 用 `facebookexternalhit / Googlebot` 取到 HTML，内含 `ytInitialPlayerResponse`：精确 `uploadDate`、完整简介、时长。**380/380 全部拿到日期** |
| 字幕 / 文字稿 | ❌ 不可用 | 该路径下 `captions` 为空且 `playabilityStatus: UNPLAYABLE`；`timedtext` 与 `get_transcript` 均因签名/风控返回空或 400 |
| 简介中的频道内链接 | ⚠️ 需清洗 | 表面有 1356 条链接，但 **164/380** 篇简介共用同一段「✳️ 其他期权视频」模板，逐条照收会得到一张假关系网 |

### 由此得到的两个关键判断

**1. 标签：播放列表最可靠。**
15 个播放列表正好对应频道自己的栏目划分（期权的重要思想 / 交易心理重塑和市场理解 / 使用定量处理线性市场 …），直接用播放列表名作标签，按收录关系分配，一个视频可属多个标签。9 个视频同时在 3 个播放列表里。未被收录的 91 个视频归入「未归类」。

**2. 引用：必须按「区块语义」判断，不能按「有链接」判断。**
简介里的链接分成三种性质，混在一起处理会出错：

- `✳️ 其他期权视频：` / `其他定量视频：` —— 逐期复制的模板清单（出现 165 / 8 次），**不是引用，剔除**；
- `✏️ 视频中推荐的本频道其他资料和视频（按出现顺序排列）：` —— 作者主动列出的引用，**保留**；
- `系列视频链接👇：` / `相关视频链接：` —— 作者列的系列清单，**保留**。

清洗后得到 **34 条真实简介引用**。除此之外，字幕不可得，正文里也没有「上一期/承接前文」这类可解析的交叉指代（全频道只有 1 处），因此这一条只留下 1 条待人工确认的记录——这是数据事实，不是筛选阈值的问题。

**3. 系列结构是另一条可验证的线索。**
标题里存在明确的系列标记：`（第一集…第八集）`、`[上]/[下]`、`Day 1–5`、`XX系列 - `。同一系列内按集数/日期串联，得到 **25 条系列关联**。这类关系在页面上用**虚线 + 紫色**区分，不冒充「明确引用」。

> 最终：**59 条关联**（34 条简介引用 + 25 条系列关联），1 条待确认。没有为了凑数把模板清单算成引用。

## 二、目录结构

```
PUG_VideoMap/
├── index.html            # 公开版（构建产物，含内联数据，可直接双击打开）
├── dev.html              # 开发版（同上，多出编辑能力）
├── data/
│   ├── manual.json       # 人工维护覆盖层（唯一需要手改的文件）
│   └── index.json        # 构建出的结构化数据（检查/复用）
├── tools/
│   ├── collect.py        # 采集：视频列表 / 播放列表 / 逐条元数据（带缓存）
│   ├── build.py          # 清洗 + 归并 + 打包成 index.html
│   └── refresh.sh        # 一键更新
├── web/                  # 页面源码（模板 / 样式 / 逻辑 / 笔记编辑器），改完需重新 build
│   └── note.js           # Markdown 子集 + Notion 风格块编辑器
└── raw/                  # 原始抓取缓存（可删，重跑会重建）
    ├── collected.json
    ├── videos/<videoId>.json
    └── playlists/<playlistId>.json
```

## 三、更新流程

```bash
./tools/refresh.sh          # = collect.py + build.py
```

首次采集约 3–5 分钟（380 个视频页，6 并发）；之后有缓存，只抓新增视频，通常几十秒。

`collect.py` 只负责取数，`build.py` 负责清洗与合并，两者都幂等。频道后续新增视频时：新视频自动进入列表、拿到日期、按播放列表分配标签、按标题规则并入既有系列，**`manual.json` 里的人工修订按视频 ID 保留，不受影响**。

本节只到「本地生成 `index.html`」为止；要发布到线上（GitHub Pages）见文末第七节。

## 四、人工维护：`data/manual.json`

以 YouTube 视频 ID 为索引，全部字段可选，缺省即「不覆盖」：

```jsonc
{
  "tags": {
    "pZRmCv-kfmc": {
      "add": ["PLFzeuKbRQ3c1Scw3lQv8Einmv2L_H-yJR"],   // 加标签（可用播放列表 ID，也可用自定义标签 ID）
      "remove": ["unfiled"]                             // 去掉自动分配的标签
    }
  },
  "refs": {
    "pZRmCv-kfmc": {
      "add": [{ "to": "CC0dUapaBLU", "type": "mention", "note": "开场提到上一期" }],
      "remove": ["agJUm5hxZLs"]                        // 删掉自动推断的关联
    }
  },
  "notes": {
    "pZRmCv-kfmc": "## 2026 年度回看\n\n把全年 54 期做了一次索引，适合当入口先看。"  // 视频笔记，Markdown
  },
  "tagDefs": [
    { "id": "theme-0dte", "label": "0DTE 专题", "color": "#e0895b" }
  ],
  "pendingDismissed": ["oXjxx5jH2gw"]                  // 已审阅、无需处理的待确认项
}
```

- `type`: `mention`（明确引用，实线蓝）或 `series`（系列关联，虚线紫）。
- 自动与人工的合并规则：**自动结果 ∪ add − remove**；同一目标同时存在两类来源时，以 `mention` 为准。
- 规则在 `web/app.js` 的 `mergeTags / mergeRefs` 与 `tools/build.py` 中保持一致；页面运行时也用同一套规则合并，所以网页上的改动与文件改动效果完全相同。

### 在网页上改，再固化回文件

在 **`dev.html`** 上操作：

1. 点行内空白写笔记；点行尾「编辑」改标签与引用；
2. 勾选/取消标签、`×` 删除引用、输入标题搜索并新增引用；
3. 改动**即时写入浏览器 `localStorage`**，页脚显示「本地已保存 12:28:53」，刷新或下次打开都还在；关标签页/切后台前会再落一次盘；
4. 点「**提交**」把改动直接写回仓库（见下），或点「导出修订 (n)」下载 `manual.json` 手动覆盖后 `./tools/deploy.sh`；
5. 「重置」丢弃本地暂存，回到文件版本。

### 自动同步：改完就写回仓库，所有设备可见

首次点右上角「同步」，填三项并勾上「自动同步」：

| 字段 | 填什么 |
|---|---|
| 仓库 | `owner/repo`，在线上打开时会自动带出 |
| 分支 | 一般是 `main` |
| Access Token | GitHub 细粒度 Token，权限只要 **Contents: Read and write**，且限定这一个仓库 |

配置一次之后，**改完停手约 2 秒就自动提交**——笔记、标签、引用、忽略记录都算。页脚会依次显示「待同步…」→「同步中…」→「已同步 13:40:09」。其他设备打开页面或切回标签页时自动拉取，约 30 秒后 CDN 也更新。

**不会互相覆盖**：提交前先读远端，只把你**这次改动过的那些视频**的条目盖上去，其余保持远端版本。所以在 A 设备改第 5 期、B 设备改第 20 期，两边都会保留。如果远端在你读取之后又被抢先更新，会自动重读并重试一次。

**失败不丢数据**：页脚显示「同步失败 · 仅存本地（原因）」，内容仍在浏览器里；修好 Token 后自动补同步（未同步标记会跟着本地数据一起保存，下次打开检测到就重试）。

Token 只存在这台浏览器（`localStorage`），不进仓库。建议设过期时间，随时可吊销。**不要用带 `repo` 全权限的经典 Token。**

手动退回：把「自动同步」取消勾选，就只在点「立即同步」时提交。

### 页面是怎么拿到最新数据的

`index.html` / `dev.html` 启动时会去拉同目录的 `data/manual.json`（带时间戳参数绕开缓存），拉到就用它，拉不到（`file://` 打开、离线）才退回 HTML 里内嵌的那份副本。

所以：

- 只改 `manual.json`（自动同步或手动 commit）**不需要重新构建 HTML**，30 秒后全网生效；
- 新增视频、改标签体系这类要重跑 `collect.py` + `build.py` 的，仍然走 `./tools/deploy.sh`；
- 单文件拷走的场景依然成立——内嵌副本保证离线可用。

**跨设备同步的本质**：`localStorage` 只在本机，真正同步靠的是仓库里的 `manual.json`。自动同步把「停手 2 秒」当触发条件，等价于把它当成一个远端存储来用。

关于持久化，有三点边界要知道：

- **按来源隔离**：线上 `dev.html`（`hrlovefun.github.io`）与本地双击打开的文件（`file://`）是两套存储，各记各的；换浏览器、换设备也不同步。
- **无痕/隐私模式**通常禁用存储，这时会弹出红色提示「浏览器禁止本地存储」，改动只在当前页有效——那种情况下请改完立刻「导出修订」。
- 想在多设备长期保存，**唯一可靠的载体是 `manual.json`**（导出 → 覆盖 → 部署），`localStorage` 只是本机的临时工作区。

## 五、页面交互

- **列表**：380 行，按发布日期从新到旧；列为 `发布日期 / 视频名称 / 引用`。点击标题在新标签页打开原视频。左侧 3px 色条是标签染色（多个标签则是分段渐变），悬停可见标签名。
- **筛选**：顶部「全部」+ 15 个播放列表标签 + 自定义标签 + 「未归类」。可多选，取**并集**；「全部」恢复。支持标题搜索，搜索与标签叠加生效。页面长度跟着筛选结果走（380 行约 13 000px、103 行约 4 000px、3 行约 700px），不会留下一条长长的空白滚动区。
- **引用标记**：一行只有**一个**小圆点，与这一行引用了几条无关——有引用才出现。悬停可见它指向哪些视频（多个时列出前 4 个与总数）。同系列内部互相提到的视频不再单独出点，交给下面的方框表达，避免六期互引变成六条重复连线。
- **连线**：点圆点 → 一次性高亮该行引用的**全部**目标，并在右侧留白处为每个目标画一条带箭头的贝塞尔曲线；再次点击取消。可以同时展开多行，曲线并存。`Esc` 清空全部。
- **系列关联**：同一系列的连续几期用**圆角方框**圈在一起，方框不做点击交互，悬停显示系列名与期数。若同系列的两期之间夹了别的视频（例如上下集之间插了一条无关更新），方框会分成两段，并在右侧用一条紫色虚线把它们串起来；筛选把成员打散时同样处理。
- **临时展开**：若某个目标行被当前筛选隐藏，点圆点时强制显示该行并标「临时」；取消后自动收回，筛选状态不变。
- **视频笔记**：每行标题下可挂一段笔记，公开版只读展示（超过 3 行折叠，点击展开），开发版点行内空白处直接编辑。

**待确认**：右上「待确认」打开审阅面板。面板顶部解释了这一栏的含义——简介正文里出现「承接之前的内容」「上一期讲过」这类说法，能确定它「提到了本频道的某个视频」却无法确定是哪一期，系统不猜，集中列出来等人工判断；每条给出命中原句，可一键关联到同系列候选、跳转定位或标记忽略。

### 笔记编辑器（仅开发版）

点行内任意空白（日期列、标题右侧、行尾）展开面板，标题处仍是原视频链接，两者互不干扰。

编辑器按块工作，敲 Markdown 标记会自动变成对应块，像 Notion 一样：

| 输入 | 变成 |
|---|---|
| `# ` / `## ` / `### ` | 一 / 二 / 三级标题 |
| `- ` 或 `* ` | 无序列表（回车续行，空行回车退出） |
| `1. ` | 有序列表（自动编号） |
| `> ` | 引用块 |
| ` ``` ` + 回车 | 代码块 |
| `**粗体**`、`*斜体*`、`` `代码` ``、`[文字](链接)` | 行内格式，闭合符号打完即转换 |

回车新建块、行首退格删除或合并块、多行粘贴自动拆块。内容以 Markdown 存进 `manual.json` 的 `notes`，所以既能在编辑器里所见即所得，也能直接手改文件。

改动实时存入浏览器 `localStorage`，点「导出修订」下载 `manual.json`，覆盖 `data/` 下的同名文件再构建，才会进入线上。公开版只读构建产物，不读 `localStorage`——所以访客看到的永远是已发布的版本。

### 响应式（PC / 平板 / 手机）

| 宽度 | 布局 |
|---|---|
| ≥ 1081px | 完整三栏，右侧留 104px 连线槽 |
| 821–1080px | 列宽略收，连线槽 88px |
| 561–820px | 平板：再收一档，仍保留连线 |
| ≤ 560px | 手机（iPhone 17 ≈ 393pt）：标签栏改横向滚动、标题最多两行、连线隐藏、系列方框保留、待确认抽屉变通栏 |

手机上做的针对性处理：

- **标签栏**不再换行堆成三排，改成单行横向滚动，右缘加渐隐遮罩提示还能滑。
- **标题允许两行**（`-webkit-line-clamp:2`），否则 393pt 宽只够显示半句。
- **输入框字号提到 16px**，规避 iOS 聚焦时自动放大页面。
- **可点区域放大**：`pointer:coarse` 下圆点、编辑按钮、标签的最小热区提到 32px 以上。
- **刘海与home indicator**：左右用 `env(safe-area-inset-*)`，底部留白避开手势条。
- **尊重系统「减少动态效果」**：`prefers-reduced-motion` 下关闭入场与高亮动画。

## 六、已知限制

- **字幕不可得**，所以「视频里口头提到某期」无法自动识别。若日后拿到文字稿（如自行导出），可在 `tools/` 里加一个解析器，产出与 `extract_description_refs` 相同结构即可并入，页面无需改动。
- 系列顺序：有集数/上下集的按编号；`XX系列 - ` 这类无编号的按发布日期串联，顺序为推断值。
- 发布日期取 YouTube 返回的 `publishDate`（美西时区），与频道页面显示一致；极端情况（太平洋时间深夜上传）与本地日期可能差一天。
- 播放列表归属是抓取当时的快照；频道调整播放列表后需重跑 `collect.py`。

### 日常更新

| 改什么 | 命令 | 耗时 |
|---|---|---|
| 页面样式 / 交互 / 文案（`web/`） | `./tools/deploy.sh` | 十几秒 + Pages 30 秒 |
| 频道有新视频、播放列表变了 | `./tools/deploy.sh --refresh` | 通常几十秒（有缓存只补新增） |
| 手工调标签 / 引用 | 页面「维护」→ 导出 `manual.json` → 覆盖 `data/manual.json` → `./tools/deploy.sh` | 半分钟 |

`deploy.sh` 依次做：构建 → 提交 → 推送 → 打印地址。推送后 Pages 自动重建，**分享链接始终不变**。

构建是幂等的：数据没变时沿用原时间戳，所以没改动不会产生空提交（脚本会直接提示「没有变化」并退出）。等价的手动步骤：

```bash
python3 tools/build.py
git add -A && git commit -m "update" && git push origin main
```

### 本地预览

改完直接双击 `index.html` 就能看效果，不必先部署。文件是自包含的，双击、放到任意静态目录、或发给人都是同一份。

### 三个容易出错的地方

1. **`data/manual.json` 是唯一需要手填的文件。** 页面上「维护」模式的改动只存在浏览器 `localStorage` 里，必须点「导出修订」下载、覆盖到 `data/` 下、再部署，才会固化进线上。漏了这一步，换台电脑或清缓存就没了。
2. **换机器要两步。** `gh auth login`（否则推不上去）+ 首次跑 `--refresh` 重建 `raw/` 缓存（约 3MB，没进仓库）。之后照常。
3. **回滚。** 单次改动：`git log` 找到旧提交，`git revert <sha>` 后再 `deploy.sh`；整棵树回退：`git checkout <sha> -- .` 再提交。

### 说明

- `raw/`（抓取缓存）和 `.workbuddy/`（本地工作记忆）已在 `.gitignore` 中排除，不会进仓库；换台机器 clone 下来跑一次 `collect.py` 即可重建。
- 只想要成品：仓库根目录的 `index.html` 就是全部，拷走这一个文件放任何静态托管都能用。
- 提交身份已设为中性（`PowerUpGammas Index <noreply@github.com>`，仅本仓库生效），不会带出个人信息。
